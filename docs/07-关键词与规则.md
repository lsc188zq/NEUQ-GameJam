## 本期关键词

# 编译

**围绕"编译"做设计。** 具体往哪个方向想，下面给了五个角度。

---

## 「编译」可以怎么理解

| 角度 | 在想什么 |
|---|---|
| **转换** | 输入一样东西，输出另一样东西。原材料 → 成品 |
| **组合** | 零散的零件拼装成一个能运转的整体 |
| **错误** | 编译会报错。错在哪里？错误长什么样？能不能利用它？ |
| **迭代** | 编译一次不够，要反复改、反复编译，越来越好 |
| **不可逆** | 一旦编译完成，就变不回去了 |

---

## 五个机制示例

不限这些，只是帮你想。**任何一个改一改都是你自己的东西。**

| 方向 | 机制示例 |
|---|---|
| **组合** | 收集散落的"碎片"，把它们编译成一个新东西——新道具、新能力、打开新区域 |
| **转换** | 同一个输入，在不同条件下编译出不同结果。玩家要试出正确的组合 |
| **错误** | 玩家的操作会产生"编译错误"，错误会**实体化成障碍或敌人**，必须先清掉才能继续 |
| **NPC 被编译** | NPC 说的话其实是"源代码"，玩家的选择会**编译**出他接下来的行为 |
| **不可逆** | 编译一次就定型，选错了只能重开。逼玩家想清楚再动手 |

---

## 和"校园"怎么结合

题材已定为**大学校园**，2D 俯视角。几个自然的结合点：

- 计算机课 / 实验室 / 机房
- 社团活动、课程作业、实验报告
- 校园里的自动贩卖机、公告栏、门禁系统
- "编译失败"在校园语境里天然有喜感（作业交不上去）

**不限这些。** 也可以用很轻的方式结合——比如整个故事就发生在校园里，跟"编译"的关系体现在玩法上而不是画面上。

## 本期限制

| 限制 | 说明 |
|---|---|
| **场景数** | **3 个以内**（一张地图算 1 个） |
| **NPC 数** | **2 个** |
| **核心机制** | **1 个**。一句话说不清就砍 |
| **流程长度** | **3–10 分钟**能通关 |
| **题材** | 大学校园，2D 俯视角 |
| **引擎** | Godot 4.7.2 |

**为什么要限制**：这些限制是保护你的。一个月的时间，做 3 个场景、2 个 NPC、1 个机制，能做完；做一个 100 分钟的 RPG，做不完。

**做完的小游戏 > 做不完的杰作。**

---

## 动手之前，先写这一句

> 玩家做 **\_\_\_** → 于是 **\_\_\_** → 然后 **\_\_\_** → 回到第一步

举例（用"编译"）：

> 玩家**收集到两份碎片** → 于是 **把它们编译成一个新道具** → 然后**用新道具打开原本过不去的门** → 回到第一步

**写不出这句话，说明范围太大，砍。**
