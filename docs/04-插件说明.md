## ⚠️ 先看这个：为什么 `addons/` 里有 10 个文件夹，插件列表里只有 8 个

这是**正常的，不是出错**。

| | 数量 | 在「项目设置 → 插件」里 | 能删吗 |
|---|---|---|---|
| **真正启用的插件** | 8 个 | ✅ 已启用 | ❌ 不能 |
| **只提供全局类的依赖** | 2 个（`plugin_updater`、`clean_copy_examples`） | ⬜ **未启用** | ❌ **绝对不能删** |

**为什么这两个不能删**：菜单插件 `maaacks_menus_template` 的代码里**直接调用**了它们的全局类：

```gdscript
PluginUpdater.add_plugin(...)        # plugin_updater 提供
CleanCopyExamples.add_examples(...)   # clean_copy_examples 提供
```

删掉它们，菜单插件会**解析失败并被 Godot 自动禁用**，菜单就没了。

**为什么它们不用启用**：这是最容易搞混的一点——

> **`class_name` 全局类是在 Godot「扫描项目文件」时注册的，跟插件启不启用无关。**

只要**文件夹在**，全局类就能被找到；而**不启用**意味着它们的插件代码**一行都不会执行**——不会联网、不会改菜单。

**结论：保持现状，别动它们。** 看到插件列表里没有这两个，是对的。

## ⚠️ 三条铁律

1. **不要修改 `addons/` 里的任何文件。** 那是插件本体，改了会出各种怪问题，而且下次更新会被覆盖。你要改的是 `scenes/`、`scripts/`、`content/`、`assets/` 这些。
2. **不要删 `addons/` 里的 `LICENSE` 文件。** 这些插件都是 MIT 协议，允许我们打包分发，**唯一的要求就是保留许可证文本**。删了就是侵权。
3. **插件出问题时，先去「项目设置 → 插件」看有没有启用。**

## 1. Dialogue Manager · 对话系统

**干什么**：让你用**写剧本一样的方式**做对话，支持分支、条件、随机台词，而不用写 `if/else`。

**怎么用**：在 `content/dialogues/` 里建 `.dialogue` 文件，语法长这样：

```
~ 开始

老师: 你好，新同学。

- 我是来报到的。 => 报到
- 我就是路过看看。 => 路过

~ 报到
老师: 好，去把这份材料交到教务处。
$> GameState.set_flag("accepted_quest", true)
=> END

~ 路过
老师: 那你随便看看吧。
=> END
```

**要点**：
- `角色名: 台词` 就是一行对话
- `- 选项A => 跳转目标` 是分支选项
- `~ 名字` 是一个段落（可以跳过来）
- **`$>` 开头的行是执行代码**——这是对话和任务系统连起来的方式
- `=> END` 结束对话

**中文会不会显示成方块？** 项目里已经打包了中文字体，正常情况不会。如果出现方块，去看 `06-常见问题.md`。

**它自动注册了一个全局对象 `DialogueManager`**，在「项目设置 → 自动加载」里能看到。**这是正常的，别删。**

**官方文档**：https://github.com/nathanhoad/godot_dialogue_manager

## 2. QuestSystem 2 · 任务系统

**干什么**：管理任务的"接受 → 进行中 → 完成"这套流程。

**怎么用**：
- 任务定义是 `.tres` 资源文件，放在 `content/quests/` 里
- 任务有了状态变化会发信号，UI 可以监听它来更新任务提示
- **在对话里用 `$>` 调用它**，比如接受任务、推进进度、标记完成

**改任务名、改条件、改奖励**：直接在 Godot 里双击 `content/quests/` 里的 `.tres` 文件，在检查器里改，**不用写代码**。

**官方文档**：https://shomykohai.github.io/quest-system/

## 3. Maaack's Menus Template · 菜单

**干什么**：主菜单、选项菜单、暂停菜单、制作人员名单、按键/手柄导航——**这些全都做好了，你只需要配置**。

**为什么要有它**：每个小组都要做菜单，而从零做菜单是个大坑（焦点处理、暂停时游戏要不要继续跑、分辨率、手柄）。这个插件把坑填了。

**你主要做的**：
- 改菜单上的文字
- 把"开始游戏"按钮指向**你自己的游戏场景**
- 决定要保留哪些菜单

**⚠️ 项目里有一堆它的示例场景**，跟你的游戏无关。别被搞混——读它自带的文档搞清楚哪些是演示。

**官方文档**：https://github.com/Maaack/Godot-Menus-Template

## 4. Maaack's Scene Loader · 场景加载

**干什么**：切换场景，并且自动带**加载画面 + 进度条 + 出错提示**。

**怎么用**：它注册了一个全局对象 `SceneLoader`。切换场景时用它，而不是 Godot 自带的 `change_scene_to_file()`：

```gdscript
SceneLoader.load_new_scene("res://scenes/world/test_map.tscn", "fade")
```

**你基本不用改它**，知道有这么个东西、切场景用它就行。

## 6. Maaack's UI Sound Controller · 界面音效

**干什么**：**自动**给按钮、标签栏、滑块挂上音效——你不用给每个按钮单独写代码。

**怎么用**：准备好音频文件，在配置里指一下。默认它就工作了。

## 7. Godot State Charts · NPC 状态机

**干什么**：用**可视化的状态图**管理 NPC 的行为。比如"待机 / 巡逻 / 和玩家对话中"这三种状态，以及它们之间怎么切换。

**为什么用它而不是一串 `if`**：NPC 状态一多，`if` 会变成一团乱麻。状态图在编辑器里就能画出来，而且**运行时能可视化地看到当前在哪个状态**，调试非常方便。

**你什么时候会碰**：想让 NPC 多一点行为时（比如"玩家靠近就跑开"、"白天和晚上行为不同"）。**在编辑器里连线和设条件，大部分情况不用写代码。**

**官方文档**：https://derkork.github.io/godot-statecharts/

## 8. Godot AI · AI 助手桥接

### 这是什么

它让 **AI 助手（比如 Claude Code）直接操作你的 Godot 编辑器**——建节点、改属性、写脚本、跑测试，不用你自己点。

**这是 8 个插件里唯一一个大多数人用不了的**，原因见下。

### 为什么你可能用不了

它本身只是"桥"，**真正干活的是 AI 客户端**。而主流的 MCP 客户端（Claude Code 等）**是付费订阅制**。

所以：**没有 AI 客户端订阅的话，这个插件装在项目里对你没有任何影响**——它只是安静地待着，不会影响游戏运行，也不会拖慢编辑器。

### 如果你想用

需要三样东西：

1. **这个插件**（已经有了）
2. **`uv`**（Python 包管理器）：`pip install uv`
3. **一个 MCP 客户端**（如 Claude Code），并且要**付费订阅**

都齐了之后：
- 在 Godot 里的 **Godot AI 面板**点 **Configure** 按钮，选你的客户端
- **重启那个客户端**（MCP 服务器是在客户端启动时加载的，不重启发现不了）

### ⚠️ 安全须知

- 这个插件会让 AI **在你的编辑器里执行 GDScript**。**只连本机（127.0.0.1），绝对不要绑 `0.0.0.0`**——那等于把编辑器的执行权限开放给整个校园网。
- 别人给你一个 `.mcp.json` 配置让你照着填，**先想清楚那是什么**。

### 官方文档

https://github.com/hi-godot/godot-ai

## 附：插件之间的协作关系

你不需要记这个，但了解一下有助于理解项目结构：

```
玩家走进 NPC 的交互范围        （Area2D，我们自己写的）
        ↓
按 E → 弹出对话框              （Dialogue Manager）
        ↓
对话里用 $> 推进任务           （Dialogue Manager → QuestSystem）
        ↓
任务完成 → 背包加道具          （QuestSystem → 我们手写的小背包）
        ↓
NPC 平时在做什么               （Godot State Charts）
        ↓
场景切换 / 菜单 / 音乐 / 音效   （Maaack 那 4 个）
```
